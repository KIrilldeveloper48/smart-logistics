# План тестирования

Этот файл хранит тесты, которые нужны проекту, но не обязаны блокировать каждый небольшой коммит.
Перед добавлением нового теста приоритет отдаётся границам данных, бизнес-правилам и регрессиям.

## Уже покрыто

- Zod-контракты общих DTO, списка, деталей и ставок.
- Mapper URL/UI-параметров в payload списка.
- Mapper DTO в ViewModel: fallback-значения и флаги скрытия.
- Изоляция и reset in-memory store.
- MSW read endpoint'ы: фильтрация, пагинация, 404, скрытая история и `all=true`.

## Ближайшие обязательные проверки

- API-клиент: Zod-парсинг успешных и ошибочных ответов, стабильность query keys.
- Подключение browser worker: mock включается только в development и не влияет на production build.
- Ставки: дробный шаг без проверки через `%`, направления `Up`/`Down`, `FixPrice`, отсутствие шага и некорректная конфигурация `step <= 0`.
- Ставки: замена предыдущей ставки пользователя, пересчёт мест, синхронность list/detail/bets и стабильный порядок при одинаковой цене.

## Перед реализацией UI

- Разбор URL search params с безопасными fallback-значениями.
- Форма ставки: обязательность цены, положительное значение, `min`/`max`/`step`, отображение 422.
- Инвалидация list/detail/bets query после успешной mutation.
- MobX UI-state: только реально добавленные сценарии, например состояние панели фильтров.

## Ручная проверка перед сдачей

- Список: loading, error, empty, pagination, фильтры и адаптивность.
- Detail: ограничения видимости, маршруты, цена и состояние ставки.
- Bets: скрытая история, отменённые ставки, победитель и пустой список.
- Открытие режима ставки по прямой ссылке и успешное обновление данных после отправки формы.

## Список аукционов — отложенные проверки

- Router: некорректные search params списка получают безопасные fallback-значения; допустимые параметры восстанавливаются после перезагрузки и из URL, которым поделились.
- Фильтры: применение сбрасывает страницу на первую, сброс сохраняет `perPage`, даты преобразуются в UTC-границы суток, а значения формы совпадают с URL после повторного открытия страницы.
- Пагинация: переход на следующую и предыдущую страницы меняет `page` в URL и получает соответствующий набор записей; для 25 fixtures вторая страница при `perPage=20` содержит 5 аукционов.
- Query states: loading, error с повторной попыткой и empty state доступны пользователю и не оставляют устаревшие карточки на экране.
- Mobile filters: Sheet открывается только на мобильной ширине, закрывается после применения или сброса; MobX хранит только признак открытия панели.
- Prefetch: hover и focus карточки кладут detail в cache TanStack Query, а повторное намерение не создаёт дублирующий запрос.

## Детали аукциона и ставки — отложенные автоматические проверки

- Router: валидный `auctionUuid` открывает детали, невалидный UUID не вызывает API; `?mode=bid` открывает форму, а недопустимое значение `mode` отклоняется схемой.
- Детали: DTO-флаги скрывают историю ставок, места, адреса и контакты; nullable-поля показывают fallback без ошибок рендера.
- История ставок: покрыть loading, error с повтором, empty, скрытую историю, отменённую ставку, победителя и скрытые места.
- Форма ставки: `price` обязательна и положительна; проверяются диапазон, направления `Up`/`Down`, `FixPrice` и дробный шаг без использования `%`.
- Mutation: 422 отображается рядом с полем цены; успешная ставка закрывает форму и инвалидирует list/detail/bets query, после чего актуализируются цена и история.
