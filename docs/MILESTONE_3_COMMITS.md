# Веха 3 — список аукционов

Цель вехи: реализовать рабочую страницу списка аукционов поверх готового
контрактного API-клиента и MSW. В конце вехи пользователь может открыть список,
изменить минимальные фильтры, поделиться URL, перейти по страницам и открыть
детали аукциона без повторного запроса после hover карточки.

## Последовательность коммитов

| № | Сообщение коммита | Результат | Проверка |
| --- | --- | --- | --- |
| 1 | `feat(router): add validated auction list search` | Для `/` добавлены Zod-валидация search params, безопасные значения по умолчанию и типизированная навигация. | Некорректные параметры URL не ломают страницу и заменяются fallback-значениями. |
| 2 | `feat(auction): add list query and detail prefetch` | В `entities/auction/model` добавлены query options/hooks списка и деталей, использующие `auctionClient` и `auctionQueryKeys`. | Запрос списка получает данные через MSW; prefetch не создаёт дублирующий ключ. |
| 3 | `feat(auction): add list cards and query states` | Созданы изолированные UI-компоненты карточки аукциона, skeleton, empty и error states; DTO преобразуются в ViewModel до UI. | Карточка показывает обязательные данные и корректный primary action для доступной/недоступной ставки. |
| 4 | `feat(page): render paginated auctions list` | Страница `/` связывает search params, query и UI; добавлена пагинация с синхронизацией в URL. | Смена страницы обновляет URL и данные, loading/error/empty состояния доступны пользователю. |
| 5 | `feat(auction): add URL-synced list filters` | Реализованы минимальные фильтры из ТЗ: номер груза, статусы, тип торгов, города, даты, доступность, участие и диапазон цены. Города берутся из выделенного mock-словаря, не из UI. | Каждый фильтр отражается в URL и восстанавливается после обновления страницы. |
| 6 | `feat(auction): add mobile filters panel state` | Добавлена адаптивная панель фильтров: desktop-размещение и mobile Sheet. MobX хранит только локальное состояние открытия панели. | API-данные не попадают в MobX; фильтры одинаково работают на desktop и mobile. |
| 7 | `feat(auction): prefetch details on card intent` | Карточка prefetch'ит detail по hover/focus и ведёт на маршрут деталей, который будет реализован следующей вехой. | Повторное открытие prefetched detail использует cache TanStack Query. |
| 8 | `docs(test): plan list screen verification` | В `TEST_PLAN.md` добавлены отложенные проверки search params, фильтров, пагинации, query states и prefetch; выполнены только критичные тесты чистой логики при необходимости. | Документированы ручные и автоматизированные сценарии проверки списка. |

## Архитектурные границы

- `auctionClient` остаётся транспортным слоем; hooks TanStack Query не смешиваются с ним.
- Серверные данные хранятся в TanStack Query. MobX применяется только для UI-состояния mobile-панели фильтров.
- Компоненты, их types, helpers и tests группируются по функциональному модулю в отдельных подпапках.
- Фильтры являются частью URL. Никаких дублирующих копий фильтров в MobX или `useState`.
- До вехи деталей не реализуем её UI, историю ставок и форму установки ставки.

## Условие завершения

Веха завершена, когда страница `/` получает список через TanStack Query и MSW,
корректно отображает все query states, поддерживает минимальные URL-фильтры и
пагинацию, остаётся адаптивной и выполняет prefetch detail по intent карточки.
