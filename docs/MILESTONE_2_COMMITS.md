# Веха 2 — контракт, модели и MSW API

Цель вехи: превратить OpenAPI-схему в проверяемую runtime-модель, контрактный
API-клиент и stateful MSW-слой. В этой вехе не создаём страницы списка, деталей
или форму ставки: они будут использовать уже проверенные контракты в следующих
вехах.

## Обязательная зависимость

Первый коммит возможен только после добавления в репозиторий
`openapi.auctions.v0.json`. Схема является источником правды: нельзя заменять её
упрощёнными локальными DTO или придумывать enum-значения.

## Границы вехи

- Не подменяем Zod TypeScript-интерфейсами: типы выводятся из runtime-схем.
- Не используем MobX для кэша API и состояния MSW: серверное состояние остаётся
  в TanStack Query, а MSW-store существует только внутри моков.
- Не реализуем UI фильтров, карточек и форм: они начнутся после доступности
  проверенного клиента и моков.
- Каждый handler возвращает данные, прошедшие ту же Zod-валидацию, что и клиент.

## Условие завершения

Веха завершена, когда все четыре endpoint'а работают через MSW, mutation меняет
in-memory state, API-клиент валидирует ответы, а ключевые контрактные сценарии
покрыты тестами. Тогда можно начинать страницу списка аукционов.
