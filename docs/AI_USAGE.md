# Использование AI

AI использовался как инструмент для ускорения анализа, проектирования и реализации. Все изменения проходили ручную проверку, а коммиты создавались самостоятельно.

## Процесс работы с AI

Работа велась последовательно, небольшими проверяемыми этапами:

1. В начале был создан файл с [правилами разработки](./DEVELOPMENT_GUIDELINES.md), в котором зафиксированы основные best practices и процесс работы.
2. После изучения тестового задания был самостоятельно определён [общий план реализации](./WORK_PLAN.md).
3. Каждая веха плана была вручную разбита на небольшие логические коммиты.
4. AI помогал редактировать формулировки, форматировать планы и проверять последовательность зависимостей между коммитами.
5. Изменения реализовывались по одному логическому блоку за раз.
6. Перед каждым коммитом изменения вручную просматривались, спорные решения дополнительно обсуждались, а при необходимости запрашивался рефакторинг.

Планы и состав коммитов изначально создавались самостоятельно. AI не определял процесс разработки, а использовался для редактирования и форматирования материалов, уточнения формулировок и проверки полноты. Пример такой декомпозиции сохранён в [плане четвёртой вехи](./MILESTONE_4_COMMITS.md).

## Что было сделано с помощью AI

- Редактирование и форматирование подготовленной декомпозиции на вехи и логические коммиты.
- Первичная реализация React-компонентов, Zod-схем, TanStack Query hooks, MSW-handlers и ViewModel-мапперов.
- Подготовка рефакторингов: разделение типов, helpers, UI и mock-логики по отдельным файлам и подпапкам.
- Подготовка критичных тестов URL-параметров, ViewModel, действий карточки, формы ставки, MSW и обновления query cache.
- Формирование README, плана тестирования и этой документации.

## Самостоятельно принятые решения

- Использовать MobX только для точечного клиентского UI-state, а серверные данные хранить в TanStack Query.
- Выбрать shadcn/ui и Tailwind CSS для интерфейса.
- Придерживаться FSD, хранить типы в отдельных `*.types.ts`, helpers в отдельных файлах, а компоненты — в `*.component.tsx`.
- Использовать префикс `T` для type-алиасов и `I` для interface, а также добавлять `readonly` там, где это применимо.
- Самостоятельно проверять изменения и создавать коммиты.
- Не расширять тестовое покрытие механически, а отложенные сценарии фиксировать в `docs/TEST_PLAN.md`.
- Организовать рабочую документацию в `docs/`, оставив OpenAPI-контракт в корне проекта.

## Отклонённые или скорректированные предложения AI

- Отказ от смешивания HTTP-handlers, типов, helpers и seed-данных в одном файле; код разделён по отдельным модулям.
- Отказ от хранения серверного состояния аукционов в MobX; для него используется TanStack Query.
- Отказ от проверки шага ставки через оператор `%`; выбрано сравнение количества шагов с допустимой погрешностью для дробных значений.

## Что было проверено особенно внимательно

- Соответствие DTO и nullable-полей контракту OpenAPI; все внешние данные валидируются Zod.
- Обработка `can_set_bet`, скрытых полей деталей и истории ставок.
- Правила цены ставки: положительность, диапазон, направление аукциона, фиксированная цена и дробный шаг.
- Сценарий успешной mutation: обновление списка, деталей и истории ставок через invalidation query cache.
- Ошибка API 422 и её отображение рядом с полем цены.
- Результаты `typecheck`, `lint`, `format:check`, `test` и production build.

## Оставшиеся риски и ограничения

- MSW-store существует только в development-режиме и сбрасывается при перезагрузке страницы.
- Нет полного e2e-покрытия браузерных пользовательских сценариев; приоритетные проверки перечислены в `docs/TEST_PLAN.md`.
- Полная проверка визуальной регрессии и поведения во всех браузерах остаётся ручной.
- Интеграция с реальным backend ещё потребует проверки CORS, авторизации, сетевых ошибок и фактических payload API.

## Что можно улучшить при наличии ещё одного дня

- Добавить e2e-сценарии списка, деталей и установки ставки в реальном браузере.
- Добавить автоматическую визуальную регрессию для desktop и mobile layouts.
- Провести accessibility-аудит с клавиатурной навигацией и screen reader.
- Подключить реальный API на отдельном окружении и добавить contract/integration-проверки.
