# План работ

Порядок вех построен так, чтобы каждая следующая опиралась на проверенный
результат предыдущей. Детализацию до атомарных коммитов выполняем непосредственно
перед началом соответствующей вехи.

## 1. Контракт и фундамент проекта

- Добавить и изучить OpenAPI-схему как единственный источник правды.
- Инициализировать Vite-приложение с TypeScript и подключить базовую
  инфраструктуру: FSD, маршрутизацию, TanStack Query, MobX, формы и валидацию.
- Настроить качество кода, базовые стили, провайдеры приложения и локальный
  запуск.

## 2. Доменные модели и MSW API

- Описать контрактные Zod-схемы, типы и преобразования DTO в UI-модели.
- Создать детерминированные данные и stateful MSW-обработчики всех endpoint'ов.
- Реализовать клиент API, query keys и обработку контрактных ошибок.

## 3. Список аукционов

- Реализовать маршрут списка и загрузку через TanStack Query.
- Добавить фильтрацию, пагинацию и безопасную синхронизацию состояния с URL.
- Создать адаптивные карточки аукционов, все обязательные состояния интерфейса
  и prefetch деталей.

## 4. Детали аукциона и история ставок

- Реализовать маршрут и экран деталей с учётом всех ограничений detail DTO.
- Добавить представление маршрута, груза, организатора, условий и торговых
  параметров.
- Реализовать историю ставок, включая скрытую историю, пустое состояние и
  отображение статусов ставок.

## 5. Установка и изменение ставки

- Реализовать доступный по ссылке сценарий ставки.
- Добавить форму React Hook Form + Zod с динамическими правилами min/max/step.
- Подключить mutation, 422-ошибки, toast-уведомления и инвалидацию запросов.
- Проверить, что MSW-store последовательно обновляет данные на всех экранах.

## 6. Качество и сдача

- Добавить тесты чистой логики и проверить ключевые пользовательские сценарии.
- Проверить адаптивность, доступность, error/empty/loading-состояния и прямые
  ссылки.
- Обновить README с запуском, результатами проверки и ограничениями; добавить
  AI_USAGE.md.

## Зависимость и текущий блокер

Для начала первой вехи нужен файл `openapi.auctions.v0.json`. Сейчас его нет в
репозитории, поэтому точное проектирование DTO, enum-значений и MSW-моков
откладывается до его добавления.
