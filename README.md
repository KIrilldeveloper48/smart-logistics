# Smart Logistics

SPA для работы с грузовыми аукционами. Приложение реализовано по контракту [OpenAPI](./openapi.auctions.v0.json) и работает без backend-сервиса: в development-режиме API эмулирует MSW с in-memory store.

## Возможности

- Список аукционов с пагинацией, loading/empty/error-состояниями и адаптивными фильтрами.
- Синхронизация минимальных фильтров и страницы с URL.
- Prefetch деталей аукциона при hover или focus карточки.
- Детальная страница с организатором, грузом, требованиями к ТС, оплатой, параметрами торгов, маршрутом, контактами и историей ставок.
- История ставок с количеством участников, рейтингом, ценами с НДС и без НДС, победителями и отменёнными ставками.
- Установка или изменение ставки через форму React Hook Form + Zod; прямое открытие формы по URL `?mode=bid`.
- Проверка цены по доступности, направлению торгов, диапазону и шагу; 422 показывается у поля, остальные результаты — через toast-уведомления.
- Обновление списка, деталей и истории ставок после успешной mutation без перезагрузки страницы.

## Стек

React, TypeScript, Vite, TanStack Router, TanStack Query, React Hook Form, Zod, MSW, MobX, Tailwind CSS и shadcn/ui. Структура исходного кода следует Feature-Sliced Design.

## Запуск

Проверено на Node.js `24.12.0` и npm `11.6.2`.

```bash
npm ci
npm run dev
```

Vite выведет адрес локального приложения в терминал. MSW автоматически подключается в development-режиме.

## Как проверить основные сценарии

1. Открыть `/`, применить фильтр и перейти между страницами списка.
2. Открыть детали из карточки либо напрямую по `/auctions/{auctionUuid}`.
3. Нажать «Сделать ставку» или открыть `/auctions/{auctionUuid}?mode=bid`.
4. Проверить ошибку для недопустимой цены, затем отправить допустимую ставку.
5. Убедиться, что цена, статус и история ставок обновились после успешной отправки.

Данные MSW-store хранятся только в памяти страницы и сбрасываются после её перезагрузки.

## Структура

- `src/app` — инициализация приложения, Router и глобальные провайдеры;
- `src/entities/auction` — контракт API, клиент, query hooks, ViewModel и UI сущности;
- `src/features` — пользовательские действия: фильтры и установка ставки;
- `src/pages` — маршруты списка и деталей;
- `src/shared` — UI-примитивы, utilities и инфраструктура;
- `docs` — ТЗ, правила разработки, планы работ и план тестирования.

## Известные ограничения

- MSW заменяет backend только в development-режиме; production-сборка не содержит mock API.
- Полного e2e-покрытия браузерных сценариев пока нет; критичная логика покрыта unit и integration-тестами, остальные сценарии перечислены в плане тестирования.
